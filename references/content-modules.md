# 八模块内容标准

文档顺序即模块顺序，缺项补全后再交付。

## 模块 0：首屏结论（必须第一屏）

- 一句话怎么玩 + 最大风险
- 这份攻略给谁：人数与关系、出发日期、预算口径、住宿状态

模板句：
- 「一句话怎么玩：{核心玩法}，{节奏承诺}。最大风险：{风险1}、{风险2}，{应对}。」
- 「这份攻略是给谁做的：{人数与关系}，{日期}出发，预算{口径}，住宿{已订/待订}。」

## 模块 1：天气与穿搭

- 逐日天气表：日期 / 天气 / 气温 / 对行程影响（覆盖全部旅行日期）
- 穿搭要点：温差、风、雨、防晒、温泉泳具、防滑鞋
- 标注「出发前 48h 复查」
- 每个气温数字带 `实查 · 日期` 或 `参考 · 月份`

## 模块 2：路线总览

- 总览表：日期 / 主区域 / 核心安排 / 预订或天气风险
- 每天 1 个主区域，单程 ≤40 分钟，主玩时段放午后
- 地理聚拢：同片区景点排同一天，禁止来回跨区

### 路线优化铁律（排行程前先画方位关系）

1. **顺路合并**：同方向/同片区排同一天，不为一个点单独跑一趟
2. **路程最短**：每天总车程最小化；单程 ≥40 分钟要慎重，除非环线顺路覆盖
3. **不走回头路**：按地理线性/环线推进（A→B→C），回程即最后一站直接返回，禁止 A→B→A
4. **环线优先**：能组成「出发→…→环回」的绝不原路往返
5. **排完自查**：有没有两个点方向相反却排同一天？有没有折返？有就重排

### 一日自足原则（按天聚合，不按主题分散）

**每日卡是唯一执行源。** 判断标准一句话：**遮住其他所有模块，只看这一天，能不能照着走完？**
能回答"几点去哪、怎么去、吃什么、花多少、注意什么"，才算自足；答不上就是信息被分散了，必须搬进每日卡。

- ❌ **错误写法（按主题分散）**：行程写在每日卡、交通写在「交通衔接」、吃饭写在「在地体验」、避雷写在文末——照着走一天要来回翻四个地方。
- ✅ **正确写法（按天聚合）**：当天的交通、餐饮、费用、避雷、强度提示**全部写进这一天**；其余模块只放**跨天通用**的内容（大交通往返、预订窗口、玩法方法、安全卡、总账），并在模块内标注"当日具体安排见对应每日卡"。
- **引用而非重复**：同一家店在「本地人清单」和「Day3 午餐」都出现时，清单里写候选理由并标注「已排入 Day3 午餐」，每日卡里写当天去的具体时段与价格——**不重复描述，避免两处打架**。
- **一致性检查**：改了每日卡里的店/价格/时间，若清单或账本引用到了它，必须同步改。

## 模块 3：每日卡（每天一节）

**每个 Day 自足清单（9 项，缺一项就不算自足）**：

1. **今日主线**（一句话：今天做什么、为什么）
2. **今日路线图** —— 见下方专节（单图闭环）
3. **今日时段表**：时间 / 安排 / **怎么去（方式与耗时）** / 费用 / 说明（含预约提醒）——当天的交通进时段表，不另开模块
4. **今日三餐**（自足关键）：早/午/晚各一行——**店名 · 品类 · 人均 · 去哪个时段 · 一句避雷**
   例：`午餐｜XX 海鲜家常（往里两条街的本地店）· 人均 60–80 · 11:30 前到避开饭点 · 先问价再看秤`
5. **今日预算小计**：当日人均合计（吃+行+门票+其他），供账本汇总校验
6. **今日避雷**：当天才涉及的坑（如"今天赶海 14:20 开始涨潮，13:30 必须上岸""景区第一排海鲜店跳过"）
7. **今日强度提示**：步行约 X km / 连续户外 X 小时（带老人小孩时必写，对照强度上限）
8. **可删减项 + 备选**：明确写「删什么」；雨天/疲劳「换成什么」
9. **今日预订提醒**：当天需要提前订/预约的（门票、餐厅、包车），写清提前 N 天

到达日轻量、返程日留足赶车时间。

### 每日路线图（首选真实截图；失败走降级，四档都要如实标注）

- 让用户在出发前**看个大概**，当天实际出行仍以手机导航为准
- **首选**：高德/百度/腾讯真实「点到点」驾车路线截图——画面能看到真实路网、起终点标记、推荐路线、左侧面板「约X分钟 / X公里 / 途经道路」
- 一天多个点：分段截图后用 `scripts/make_route_maps.py` 纵向拼成一张全天图，顶部横幅标 Day、日期、主题、各段路程
- 路程/时长**照抄地图面板读数**，不按直线距离估算
- **降级四档**（详见 `references/map-screenshots.md` §4）：
  | 档 | 形态 | 必标 |
  |---|---|---|
  | L1/L2 | 真实截图 / 当日主段截图 | `高德真实地图` |
  | L3 | 仅导航链接 + 文字里程 | `未采集到地图截图` |
  | L4 | **固定方位示意图**：节点链（住处 → 各站 → 回住处／到家）+ 每段 km/车程 | `方位示意图 · 非真实路网截图 · 当天以手机导航为准` |
- **禁止只给链接**（L3 与 L4 至少要有其一）；**禁止把 L4 示意图当真实截图交付**（不标注、起像截图的名字、混进 `routes/`）。
- **禁止手工估坐标出图**：高德对任何坐标都会给出「合法」路线与读数，**有读数 ≠ 坐标对**。坐标须复核，出图后须肉眼核对起终点位置（§3.2）。
- **链路必须闭环**：每天最后一段回到住处；返程日到「到家」，不能停在半路。

## 模块 4：跨天交通与预订

只写**跨天**的交通与预订，当日怎么走已在每日卡时段表里，**不重复**：

- **大交通往返表**：去程/返程 · 车次或航班 / 时刻 / 历时 / 票价（三色标注）/ 购票窗口
- **预订窗口**：高铁提前开售天数、航班比价、热门门票提前 N 天
- **当地交通方式建议**：打车/租车/包车/公交的取舍与行情区间（不写当日具体路段）
- 每个地点附高德 URI 链接：`https://uri.amap.com/search?keyword={地名}&callnative=0`

## 模块 5：主题玩法速查 + 避雷全览 + 安全卡

跨天通用的"方法"，**不重复当日安排**（当日具体安排见对应每日卡）：

- **玩法速查**：海鲜怎么吃、温泉怎么泡、赶海怎么赶——通用方法 + 价格参考区间（标「旺季上浮」）
- **避雷全览**：五桶映射结果汇总，每条标「涉及 DayN」，具体执行仍看当日卡的「今日避雷」
- **本地人清单**：早市/老店/老字号候选池，每条写清**去哪个时段**；已排进某天的标注「已排入 DayN」（引用，不重复描述）
- **安全卡（必做）**：本地急救/报警电话、医院、过敏与肠胃应对、特殊安全（赶海涨潮/温泉时长/海边风大）

## 模块 6：预算账本（总账）

**每日卡已给出当日小计，本模块做汇总与加总校验**：

- **汇总表**：逐日小计相加，再加大交通往返与住宿等跨天项 = 全程人均
- **校验**：每日小计之和 + 跨天项 = 总账口径，**不等就重算**（是加总校验，不是重新估算）
- 优先按实查价逐项累加，给参考区间（如「餐饮 人均 120–180/天」）
- 只有用户给总额但无明细时，才用百分比法兜底：

| 项 | 占比 |
|---|---|
| 交通（往返大交通） | 35% |
| 餐饮（含特色餐） | 25% |
| 当地交通 | 10% |
| 门票与活动 | 15% |
| 购物/备用（含缓冲） | 15% |

- 表：项目 / 人均 / 合计 / 说明
- **合计必须等于预算口径**，不等于就重算
- 注明「不含住宿」或「含住宿」
- 价格标 `实查` / `参考`，旺季上浮提示

## 模块 7：出发前时间线 + 复查清单

分阶段 checkbox：

- **立即**：抢票 / 订热门景点 / 确认酒店（含电话）
- **出发前 7 天**：复查天气、微调行程
- **出发前 48h**：查潮汐 / 开放时间 / 天气终版
- **出发前 1 天**：打包核对、证件、药品、充电

打包核对按「证件 / 衣物 / 温泉 / 赶海 / 药品 / 雨具 / 电子」分类。

## 模块 8：变化应对与 Q&A

- 至少 2 组问答：下雨怎么办、累了怎么办、赶海带什么、打车方不方便
- 原则：**只删不加，绝不硬排**

## 质量门控（生成后逐项自查）

- [ ] 每天 1 个主区域，无跨区乱跳
- [ ] 到达/返程日轻量，赶车时间充足
- [ ] 单段车程 ≤40 分钟
- [ ] 预算逐项相加 = 预算口径，含缓冲
- [ ] 票价/天气/潮汐/开放时间全部实查并标注
- [ ] **每个数字都带实查/参考/待复查标注**
- [ ] 预订项有明确窗口提示
- [ ] 每个 Day 有可删减项 + 备选
- [ ] 带老人：午后主玩、下午可休整、温泉时长提示
- [ ] 安全卡在（急救/过敏/赶海涨潮/温泉禁忌）
- [ ] 无编造预订
- [ ] 双形态内容一致（同一套数据）

## 强度上限（带老人/小孩时）

| 指标 | 上限 |
|---|---|
| 单日步行 | ≤5 km |
| 连续户外 | ≤4 小时 |
| 单段车程 | ≤40 分钟 |
| 每日主景点 | ≤2 个 |
| 台阶密集景点 | 每日 ≤1 处 |

超了就删项，不靠「慢慢走」化解。

## 标题格式

- 在线文档：`带{人群}游{目的地}的{天数}天{主题}手册`
- HTML 手册 `<title>`：同名，加副题「出行随身手册」
