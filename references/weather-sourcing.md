# 天气怎么查：四源交叉 + 双保险口径

> 适用：任何行程、任何目的地。天气是行程里**唯一一个「查了也会变」的数据**，
> 所以纪律不是"查准一次"，而是"**建一套查不准也不会翻车的机制**"。

---

## 0. 为什么单源一定不够

| 源 | 优点 | 硬伤 |
|---|---|---|
| 高德气象 | 中国气象局同化数据，**最准** | `extensions=all` **只给今天 + 未来 3 天**（共 4 天） |
| 中国天气网 | 有站点级（区/县）预报，7 天内较准 | 8-15 天段**区级站点经常没数据**；40 天段是气候推算 |
| 墨迹 / 360 | 界面友好、有 15 天 | 长期段本质是气候统计，**越往后越不准**，且多源之间会打架 |
| 单一模式（GFS 或 ECMWF） | 能覆盖 16 天 | 单个模式在 7 天外**抖动很大**，一次预报当真必翻车 |

结论：**近期靠权威源，远期靠多模型取中值，全程留降级与复查口。**

## 1. 四源清单（推荐组合）

| # | 源 | 覆盖 | 定位 | 怎么取 |
|---|---|---|---|---|
| ① | **高德气象**（中国气象局） | 今天 + 未来 3 天 | **D+3 内一律以它为准** | `scripts/weather_amap.py --city <adcode/中文名> --key <用户自己的key>` |
| ② | **中国天气网 · 站点页** | 7 天（`/weather/<code>.shtml`）<br>8-15 天（`/weather15d/<code>.shtml`） | 7 天内、且该站点有数据时**以它为准** | 直接抓页面，解析 `<li class="sky…">`（7 天）/ `<span class="time">`（8-15 天） |
| ③ | **ECMWF**（欧洲中心细网格） | 全段（约 10-16 天） | 7 天外主力 | Open-Meteo：`&models=ecmwf_ifs025` |
| ④ | **GFS**（美国全球模式） | 全段 | 7 天外对照，与 ③ 打架时当"不确定信号" | Open-Meteo：`&models=gfs_seamless` |

Open-Meteo 最小请求（无需 key）：

```
https://api.open-meteo.com/v1/forecast
  ?latitude=<lat>&longitude=<lon>
  &daily=weather_code,temperature_2m_max,temperature_2m_min,
         precipitation_probability_max,wind_speed_10m_max
  &timezone=Asia%2FShanghai&start_date=<YYYY-MM-DD>&end_date=<YYYY-MM-DD>
  &models=ecmwf_ifs025        # 或 gfs_seamless
```

`weather_code` 常用值：`0` 晴 · `1` 大部晴 · `2` 多云 · `3` 阴 · `53/61/63` 雨 · `80` 阵雨。

### 1.1 节假日气象专报：趋势的权威源（2026-09-30 补）

长假（春节 / 五一 / 国庆）前 1–2 天，**省级气象局会发布整段假期的天气专报**，省媒与中新网会转载。它给的是**全省趋势 + 分区域落区 + 风力/降温/大雾/霜冻逐项提示**，权威度高于任何单城预报或 UGC。

- **检索式**：`{省}省气象局 假期 天气专报` / `{省} 国庆 天气 以晴为主` / `国庆假期 {省} 天气 气象部门`
- **它独有、单城预报给不出的信息**：
  - **落区**——"10/3 营口、盘锦、锦州等有中雨、局部大雨"，比"某城有阵雨"更能定行程；
  - **阵风级别**——"海区偏北风 6–7 级、阵风 8–9 级"，直接决定海边能否去、帽子要不要带绳；
  - **大雾 / 霜冻 / 森林火险**等次级风险（常被单城预报漏掉）；
  - **气温较常年偏高/偏低 X℃**——用来反向校验自己给的穿衣建议。
- **用法**：专报定**趋势与风险**，单城站点（中国天气网 / 高德）定**逐日数值**；冲突时按"取最坏"处理，并把冲突写在表里。
- **穿衣建议可直接引官方指数**：中国天气网站点页的「穿衣指数 / 感冒指数」是现成官方口径（如"较冷——厚外套加毛衣""极易发感冒 · 强降温风力较强"），比自己从温度倒推更稳、更省事。

> 实战（2026-09-30 鲅鱼圈）：辽宁省气象局 9/29 专报 → 10/3 营口中雨、10/1 与 10/4–5 海区阵风 7–9 级、10/4 夜间大雾、气温较常年偏低 1–3℃。
> 这几条把"10/3 雨天备选要不要启用""海边能不能去"一次性定死，比逐城预报省事且更硬。

## 2. 采信口径（双保险规则，四条）

1. **有高德的日期 → 直接采信高德**，其余三源只作参考，不参与加权。
2. **无高德但在 7 天内 → 采信中国天气网对应站点**（站点级优先于市级）。
3. **7 天以外 → 取 ECMWF 与 GFS 的中值**；
   两模型**高温差 > 3℃** 或 **降水概率差 > 30 个百分点** → 标 `参考 · 待复查`，**不装准**。
4. **只要有两源及以上报降水 → 一律按"会下雨"备方案**，不管剩下几源说晴。
   （漏带一次雨具的代价，远大于多带一把伞。）

### 输出形态：一张表给读者，一张表留底

- **逐日采信表** → **进交付物**：日期 / 天气 / 气温 / 风 / 降水风险 / 状态（这是读者真正要看的）；
  表前加一句人话说明采信规矩（"源之间不一致时按最坏的那个准备"）。
- **原始对照表**（四源原值并列）→ **只留本地工作稿，绝不进交付物正文**。

⚠️ **交付物洁净原则（v1.2.8 新增，返工教训）**
交付物是给"要去旅行的人"看的，不是给人看你查得多辛苦。以下都属于**工艺脚手架**，一律留工作稿：

- 原始对照表 / 站点代码 / 模型名称与坐标 / 脚本文件名
- 滚动复查计划（与文末待复查清单重复，写两遍）
- 内部署名（"XX 定"）、资料库文件名与时间戳
- 勘察过程描述（"穷举所有排列""喂进校验器""次序比 1.00"）

写进正文只会稀释重点，读者的行动价值 = 0。
**反面案例**：鲅鱼圈手册正文里出现「四源原始对照（不采信，留底自查）」一节——
自己标着"不采信"，却推给了读者，被当场叫停；同类还有「绕路校验」表（7 行次序比 +
脚本名）。一次返工删掉 5 处、压缩 3 处。

反之**必须进交付物**的是：逐日采信表、来源可信度标注（`实查` / `参考` / `待复查`）、
以及读者能直接用的结论（"比往年同期偏凉 3–7℃，按中值备衣"）。

## 3. 站点代码怎么找（踩过坑，别凭记忆写代码）

**中国天气网的城市代码没有可读规律，记错会查到完全另一个城市。**

- 营口城区 `101070801` / 大石桥 `101070802` / 盖州 `101070803` / 站前 `101070804`
  / 西市 `101070805` / **鲅鱼圈 `101070806`**
- 反例：`101071201` 是**辽宁朝阳（或铁岭）**，不是营口也不是鲅鱼圈。
  曾凭记忆写错，导致整版天气数据是另一座城市的，**且当时没有任何报错提示**。

**强制动作**：抓完页面后，先解析面包屑确认城市名再取数：

```python
crumb = re.search(r'class="crumbs fl">(.*?)</div>', html, re.S).group(1)
print(re.sub(r'<[^>]+>', '', crumb))     # 必须看到目标城市/区名才算数
```

**降级**：目标站点没有 8-15 天数据时，用**上级市站**补，并在文档里注明"该日使用了 XX 站补"。

## 4. 滚动补查节奏（写在文档里，别只放在脑子里）

| 时点 | 动作 |
|---|---|
| 出发前 3–4 天 | 高德查一次，把**到达日**升级为气象局数据 |
| 出发前 1–2 天 | **再查一次**，窗口滑到 D+3，把**最关键的户外日**（赶海/登山/出海）覆盖进权威源 |
| 行程中每天 | 早间滚一次，覆盖后续 3 天，当天执行"雨天备选"与否以此为准 |
| 4 天以外的日期 | 用 ③④ 中值，标 `参考`，进复查清单 |

**能自动化就自动化**：一次性自动化在出发前 1–2 天触发，跑补查并覆盖更新已交付的在线文档。
prompt 要自包含（目的地、站点代码、坐标、文档 token、四源口径），并写明
**拿不到 key 时的降级路径**（走天气网 + Open-Meteo，不要卡死）。

## 5. 天气 → 行程决策的映射（别只贴温度）

| 天气要素 | 影响什么 | 触发阈值 |
|---|---|---|
| 降水概率 | 户外日是否启用"雨天备选" | ≥ 30% 就该准备；两源报雨直接切备选 |
| 风力 | 赶海 / 出海 / 观景台 | 阵风 ≥ 6 级，滩涂与礁石区风险陡增，老人不宜 |
| 昼夜温差 | 老人穿衣、泡汤后保暖 | 温差 > 8℃ 必须在每日卡里写"加外套" |
| 低温 | **涉水玩法（赶海 / 下滩）能否留在主线** | **凌晨低温 < 12℃ 或白天最高 < 22℃** → **默认降级为备选**，主线改「岸上观光版」（规则见 SKILL.md「涉水玩法默认降级为备选」） |
| 低温（若仍下滩） | 下水体感与安全 | 高筒雨靴 + 防水裤，缩短下水时长，**只留正午前后最暖的窗口**；上岸后无淋浴设施的要提前备干衣 |
| 高温日晒 | 正午时段安排 | > 28℃ 把户外挪到 10 点前 / 15 点后 |

**每个户外日都必须配一个雨天备选**，且备选本身要可执行（不是"自由活动"四个字）。

## 6. 常见坑

1. `export_pdf.py` 那类**模板插值坑**同理：往 URL 里拼参数用 `urllib.parse.urlencode`，别手拼。
2. 天气网 7 天页与 8-15 天页的 DOM **完全不同**（`<li class="sky">` vs `<span class="time">`），
   别指望一个正则通吃；8-15 天页区级站点**经常 0 条**，必须有上级市站兜底。
3. Open-Meteo 的坐标要**核过**：区级目的地别直接用市中心坐标（鲅鱼圈 40.266°N, 122.13°E）。
4. 高德 `extensions=all` 返回 4 天是**硬限制**，不是参数没调对；别反复重试浪费配额。
5. 文档里**必须写清每个数字来自哪个源、几点更新的**（`实查 · 09-27 20:00 · 天气网鲅鱼圈站`），
   否则复查时无从判断哪个该被覆盖。
