# 每日真实地图路线图采集法

目标：为每个 Day 产出**一张真实地图「点到点」驾车路线图**——让用户看个大概，当天靠导航。
首选高德 `ditu.amap.com`，百度/腾讯备选。全程用浏览器自动化（本机为 `agent-browser` skill），**不要写爬虫**。

## 0. 成品标准

- 画面是真实路网：起/终点标记、推荐路线、左侧面板「方案1 约X分钟 / X公里 / 红绿灯N个 / 途经：…」
- 顶部深色横幅（`scripts/make_route_maps.py`）：`DayN · 日期 主题` + 各段 `起→终 约X分·Xkm`
- 一天多个点：分段截后纵向拼成一张全天图
- 时长/公里**照抄面板读数**，不估算

## 1. 准备 POI（id + 经纬度，两者都要）

URL 直达必须同时带 POI 的 `id` 和 `lnglat`，**缺坐标页面会空白并停在默认网格**。

拿坐标（每个点只需做一次）：

1. 打开 `https://ditu.amap.com/dir`，等页面加载完，再等 3 秒
2. 起点框 `#dir_from_ipt`、终点框 `#dir_to_ipt`，输入「城市+地名」，等 2.5 秒
3. **必须从候选下拉里点精确 POI**，否则会提示「请选择正确的起点、途经点或终点」。点候选用坐标点击最稳（点前先截图确认位置）
4. 点「开车去」，等 6 秒，读地址栏 URL
5. URL 解码后含 `from[id]=B0..&from[lnglat]=122.x,40.x`、`to[id]=..&to[lnglat]=..`，记录下来
6. 终点优先选**停车场/门址**（如「{景点名}P1停车场」），驾车路线更准确

## 2. URL 直达批量截图

构造 URL（免手动输入，比模拟点击稳得多）：

```python
from urllib.parse import urlencode

def dir_url(frm, to):
    # frm/to = {'id': 'B0...', 'name': '...', 'lnglat': '122.x,40.x'}
    p = {}
    for k, v in frm.items(): p[f'from[{k}]'] = v
    for k, v in to.items():  p[f'to[{k}]']   = v
    p['type'] = 'car'
    p['policy'] = '1'          # 1 = 推荐方案
    return 'https://ditu.amap.com/dir?' + urlencode(p)
```

逐段执行：

```
agent-browser open "<dir_url>"
# 等待 7-10 秒让瓦片和路线面板渲染
agent-browser screenshot
# 立即把截图另存为自己的文件名，不要留在默认路径（见 §3）
```

每张约 10 秒。**校验**：截图后确认页面文本里出现「约」字（面板出方案），否则视为渲染失败需重试。

## 3. 已验证的坑

- **途经点 via 不支持**：PC 网页 URL 的 `via[id]/via[lnglat]` 不渲染（停在默认城市、一直转圈）。全天多段只能分段截图后拼图。
- **截图文件会被覆盖**：截图默认写到固定路径，每次覆盖。必须在同一轮内**立即另存**成自己的文件名（如 `map-Day3a.png`）。
- **空白网格 / 只剩蓝点**：连续导航偶发瓦片不渲染（版权变英文 AutoNavi、定位到默认城市）。处置：重开 dir 页，或把等待加到 10–12 秒重试。
- **元素引用跨导航失效**：导航或选点后重新获取元素引用，别复用旧的；点候选用坐标最稳。
- **会话断开**：报无活动页或标签列表为空 → 重开 dir 页，元素引用全部重取。
- **登录/验证码**：路线规划页免登录可用；若弹登录或验证码，按浏览器自动化的接管规则请用户处理。

### 3.1 headless / 无交互环境实测（2026-09 补充，务必先读）

在没有 `agent-browser`（或无头 Chromium）的机器上，用 Playwright 复用本机 Edge headless 实测结论：

| 方案 | 结果 |
|---|---|
| `uri.amap.com/navigation?from=名称&to=名称` | ❌ 弹短信登录框，地图停默认城市，无路线 |
| `ditu.amap.com/dir?from[name]=X&to[name]=Y`（无坐标） | ❌ 起终点框空白，地图停 IP 定位城市 |
| `map.baidu.com/dir/driving?origin=X&destination=Y` | ❌ 参数不识别，无路线 |
| **`ditu.amap.com/dir?from[name]=X&from[lnglat]=lng,lat&to[...]=...&type=car&policy=1`** | ✅ **可行**：免登录即可渲染真实路线与左侧方案面板 |
| Playwright 真实 `click + type` 触发候选下拉 | ⚠️ 不稳定：登录遮罩反复拦截点击，多段超时；且终点框在起点选定后易失联 |

**关键结论**：
1. **坐标是唯一稳定入口**。只要拿到每个 POI 的 `lnglat`，用 §2 的 URL 直达法可稳定出图，**不需要 `id`**。
2. headless 下无 cookie → 高德必弹登录遮罩。用以下 JS 可移除（实测有效，每次导航后要重新执行）：
   ```js
   document.querySelectorAll('div,section,aside').forEach(el=>{
     const t=el.innerText||'';
     if(el.offsetWidth>180&&el.offsetHeight>100&&/登录|扫码|手机号|验证码|下载高德/.test(t)) el.style.display='none';
   });
   document.querySelectorAll('div[class*=mask],div[class*=Mask]').forEach(el=>el.style.display='none');
   ```
3. **不要用 JS 直接给输入框赋值**（React 受控组件 + 原生 setter 也不行）——高德不会触发候选搜索，结果是填了字但没选点、地图不动。
4. **拿不到坐标就走降级**。本机实测：坐标只能靠真实键入触发候选后取，而候选在 headless 下拿不到 → 果断降级，别在点击超时上耗轮次。
5. 若必须出图，先解决坐标来源：在有交互浏览器的环境跑一次 §1 流程，把 id/lnglat 存成 JSON 复用。

### 3.2 ⚠️ 手工估坐标 = 必定出错（2026-09 复审，最严重的一条）

**踩坑记录**：坐标拿不到时，用「地名大致位置」手工估了一组 `lnglat` 出了图。图看着很正常——有真实路网、有左侧方案面板、有「34 分钟 / 12.7 公里」读数——但**起终点标记落在完全错误的位置**（画成了城区内部一段南北向路，而标题写的是「A 站 → B 镇」）。距离读数与真实值接近纯属巧合。用户一眼就看出不对。

**根因**：高德对**任何**坐标都会算出一条合法路线并给出读数，所以「有读数」**完全不能证明坐标正确**。坐标错 → 图和标题不符，属于比没图更糟的交付。

**硬规则（必须执行）**：
- **禁止手工估算 POI 坐标出图。** 没有权威坐标（§1 流程取回 / 官方坐标拾取 / 结构化地理数据）就**不出真实图**。
- 拿到坐标后**必须交叉校验**：用 OSM Nominatim（`https://nominatim.openstreetmap.org/search?q=地名&format=json`）或地图坐标拾取工具复核经纬度，再比对相邻点的**直线距离量级**是否与路网距离自洽（直线应小于路网，且比例合理）。
- **出图后必须肉眼核对**：截图里起终点标记是否落在可辨识的地标附近（比对图上 POI 文字），标题与图内实际路线是否一致。**不核对就不算采集完成。**
- 一个易错点：**带有「镇」「新区」「度假区」字样的地点，实际位置常与城区主体方向相反**（如城区沿海、该点却在内陆一侧，相距 10–20 km）。别想当然按方位字面估，先查经纬度再画。

### 3.3 ⚠️ staticmap 的 URL 长度硬上限（2026-09-30 补，跨省长路线必读）

用 `restapi.amap.com/v3/staticmap` 出图时，**整条 URL 有硬上限（实测约 2100 字符）**。超了它**不报"太长"**，而是返回
`{"status":"0","info":"UNKNOWN_ERROR","infocode":"20003"}` —— **极易被误判成限流或 key 失效**。

实测（北京 → 双台镇，`driving` 返回 4493 个 polyline 点）：

| 请求组合 | URL 长度 | 结果 |
|---|---|---|
| markers（2 点）only | 1140 | ✅ |
| paths（抽稀 80 点）only | 2111 | ✅ |
| paths（抽稀 80 点）+ markers | 3152 | ❌ 20003 |
| paths（抽稀 6/12/18 点）+ markers | 1317–1613 | ❌（当时仍在限流窗口，未复现；间隔 10s 后 80 点 only 又成功） |

**处置规则**：

1. **20003 先怀疑两件事**：① URL 超长；② 短时限流——**连续请求会返回一模一样的 20003**。处置是先**间隔 3–5 秒重试**，仍失败再按超长处理。
2. **长距离（>100km）路线**：paths 抽稀到 **≤60 点**；仍超限就**放弃 markers，只画路线**，起终点在标题条/图例里用文字说明（本次采用此形态）。
3. **`size` 上限 1024\*1024**：传 `1280*720` **不报错但静默返回 1024 宽**，别把它当"放大画幅"的手段。
4. **画幅不够时降 zoom，不要加大 size**：1024px 宽在 z7 只覆盖约 960km（40°N）；北京 → 鲅鱼圈跨度 494km 直线 / 680km 路网，z7 装不下 → **降到 z6（约 1900km）** 才全程入图。
5. **出图后必须肉眼核对起终点是否都在图内**——z7 时起点/终点常被裁在边缘外（本次第一张北京就掉出了画面）。
6. 复用 `scripts/gen_maps_amap_api.py` 出跨省图时，用小脚本 `import` 它并覆写 `G.thin` / `G.auto_zoom`，**不要改 skill 本体**；底部图例第 3 行的"闭环回到住处"是写死的，单程（去程）图需自带叠加函数替换文案。

### 3.4 ⚠️ 图内标注必须与「改了行程之后的手册」对齐（2026-09-30 补）

出图脚本把 **Day 号 + 日期** 直接**烧进 PNG**（标题条 `DayN · 主题`、副标题 `日期 · 起点终点均为住处（闭环）`）。
一旦行程改动，**图内标注会静默过期**——这正是最危险的一类错：图上看着完全正常，只是写着别的日子。

**触发条件（命中任一就必须全量重核每一张图）**：

- **出发日变了**（提前/推迟）→ 全部 Day 的**日期**都要 +1/−1；
- **两天顺序调换了**（如「南线日」与「熊岳日」互换）→ 这两张图**整张归属对调**，`day-DayN.png` 里装的会变成别的日子。

**2026-09-30 鲅鱼圈实战（一次性踩满两条）**：去程由高铁改顺风车、出发日提前到 9/30 夜，于是整条行程前移一天、且南线日与熊岳日互换了 Day 号。结果 `routes/` 里
`day-Day3.png` 装的是**熊岳片区（10/3）**、`day-Day4.png` 装的是**南线海岸（10/4）**，Day2–Day7 的图内日期**全部比手册晚一天**（10/2–10/7 应为 10/1–10/6）。
首轮交付时无人发现——因为**没人看图里那行小字**。**图内文字属于交付内容，必须与手册逐字对齐。**

**验收（确定性，不靠肉眼）**：`grep -o 'src="data:image' 手册.html | wc -l` 应等于天数；再按「以 `Day N` 开头的标题之后、下一个标题之前」切片，断言每片**恰有 1 张图且是 `day-DayN.png`**。
注意切片判据要用 `re.match(r"Day\s*N\b")`——用 `re.search` 会误命中 `🦀 海鲜怎么吃（涉及 Day2、Day3、Day5）` 这类**交叉引用标题**，产生假阳性。

**修法（换日/调序后不必重新请求高德）**：坐标没变、路线没错，**错的只是烧进去的那行字**。重取坐标反而会让手册里 `实查` 的 km/车程漂移。正确顺序：

1. **交换文件归属**：`mv day-Day3.png t && mv day-Day4.png day-Day3.png && mv t day-Day4.png`（让「文件名的 Day 号」与「图内内容」重新一致）；
2. **只重绘两条文字带**（标题带 `y=0..48`、日期带 `y=48..80`），保留底图、路线、里程读数；
3. **填底不留接缝**：从带内**空白行**取一条横条**纵向拉伸**铺满该带（逐列保留底色），不要整块填单色——单色会在带边界留下可见的矩形色差；
4. 标题带被覆盖后，**右侧「全程 X km / 约 Y min」读数要按元数据原值重画**（`font(24, True)`、右对齐 `W-22, y=20`、色 `#FFD08A`）；
5. 改完**逐行验像素**：与备份图做差，断言**差异只落在允许的两条带内**（本次 6 张图全部 `带外改动=0`）。

> 判据提醒：**"图里有内容"不等于"图是对的那一天的"**。交付前把每张图的标题行读一遍，比在线文档排版好看重要得多。

**不止 Day 号与日期：图内「文案口径」也会过期**（2026-09-30 第二批修正）。同一次行程改动还留下三类文字：

| 位置 | 过期写法 | 为什么错 | 改法 |
|---|---|---|---|
| 标题（主题） | `Day2 · 赶海核心日` | 手册已把赶海**降级为备选**、当天正名「海岸观光日」——图内仍把备选玩法当核心，**与涉水降级硬规则直接冲突** | 与手册当天标题口径对齐 |
| 标题（主题） | `Day6 · 不出镇` | 当天含可选的红旗大集（在镇外） | 改成手册同名主题 |
| **副标题** | `10/6 · 起点终点均为住处（闭环）` | 返程日是**单程**去车站，不闭环——副标题模板 `%s · 起点终点均为住处（闭环）` 是**写死的**，返程/单程日不适用 | 单程日改为 `起点 → 终点（单程）` |
| **底注** | `… · 闭环回到住处` | 同上，返程日底注写「闭环回到住处」是错的 | 单程日改「单程到站」 |

**底注行的重绘窗口**（本模板 `overlay()` 版面，图高 720）：底注文字在 `y=697..708`，其上 `y=677..696`、其下 `y=709..719` 均为空白 → **取 `y=682..692` 的横条拉伸铺满 `y=695..712`，再在 `(22, 694)` 用 `font(13)`、色 `(150,168,190)` 重画整行**（底注是整行重绘，不是只换尾句——同法的前提是上下都有空白行）。

**自检升级**：`scripts/check_handbook_render.py` 只能验「对位、不重不漏」，**验不了图内文案是否过期**。文案这一层**只能靠人读**——所以 §3.4 的验收必须包含「把 7 张图的标题行 + 副标题 + 底注拼成一张联络图，一次读完」，比逐张点开快得多。

## 4. 降级链（重要）

真实截图采集失败时**按级降级，不要硬撑**，每一级都要在文档里如实标注：

| 级别 | 做法 | 标注 |
|---|---|---|
| **L1** | **单图闭环法**：`AMap.Driving` 带 `waypoints` 一次画出全天路线（首选）；不可行时才分段截图纵向拼接 | `高德真实地图` |
| **L2** | 只截「住处 → 当天最远点」一张（沿途其他点在图上可见） | `高德真实地图（当日主段）` |
| **L3** | 无图：高德 URI 导航链接 + 文字路线（每段方位与实测车程） | `未采集到地图截图，请按链接导航` |
| **L4** | **固定方位示意图**：无底图/无路网，只画「住处 → 各站 → 回住处」的节点链，标注每段 km/车程，含闭环（末站回到住处／到家） | 图下必须写 `方位示意图 · 按实查里程与方位绘制（非真实路网截图） · 当天以手机导航为准` |

**同一段失败两次就降级，不纠缠。**

**L4 使用纪律**：
- L4 是**用户可接受的低成本形态**（用户明确说「固定的就行」时可直接用），适合手机随身看流程、打印、离线。
- L4 **必须**：① 按真实经纬度定方位，不凭感觉；② 每段标实查 km/车程；③ **闭环到底**——每天链路最后必须回到住处，返程日回到「到家」，不能停在半路；④ 明标「非真实路网截图」。
- **绝不允许的**：把 L4 示意图当成真实截图交付（不标注、起个像截图的名字、混进 `routes/` 目录）。**错误或冒充的地图比没有地图更糟。**

## 5. 出全天图：单图闭环（首选）

**用户要的形态是「每天一张图、含全天所有途经点、A→B→C→回到 A」——一张图，不是分段拼图。** 首选做法：在高德页面内用 `AMap.Driving` 带 **途经点** 一次算完整条链，页面自己就把全天路线画在同一张底图上。

```js
// 在页面上下文里执行（Playwright evaluate）
const driving = new AMap.Driving({ map: map, policy: AMap.DrivingPolicy.LEAST_TIME });
driving.search(
  new AMap.LngLat(homeLng, homeLat),          // 起点＝住处
  new AMap.LngLat(homeLng, homeLat),          // 终点＝回住处（闭环）
  { waypoints: [new AMap.LngLat(a), new AMap.LngLat(b)] }   // 途经点＝当天各站，顺序即行程顺序
);
// result.routes[0].distance / .time 即全天读数，可直接拿去核对分段实测值
```

要点：
- **闭环**：起点＝终点＝住处（首末日为「站 ↔ 住处」），链路绝不半路停。
- 途经点顺序 = 行程顺序；改了顺序要重出图，并复跑 `check_route_geometry.py` 确认没绕路。
- 出图后**肉眼复核起终点落位**（见 §3.2），再裁掉登录遮罩与无关浮层。
- 读数与分段实测值对照，差得离谱说明坐标错了，别急着交付。
- 成品命名 `routes/day-DayN.png`（在 `routes/` 下），文件名带 `-day` 便于区分旧的拼接图。

### 5.1 次选：分段截图 + 纵向拼接

单图法受环境限制做不出来时，退回分段截图拼接：

```bash
python scripts/make_route_maps.py --config route_config.json
```

配置顶部改：每天的标题、横幅副标题、分段截图路径。单段直接出图，多段纵向拼接并统一宽度。输出 `final/final-DayN.png`。
**拼接图要在文档里说明「分多段拼接」，不要暗示是一张连续路线图。**

## 7. 备选地图

高德不可用时同思路替换：
- 百度 `map.baidu.com/direction`
- 腾讯 `map.qq.com`

URL 参数不同——先手动搜一次路线、观察地址栏参数再批量。成品要求不变：真实路网 + 点到点 + 面板路程。

## 8. 图怎么交付到手机（硬规范，2026-09 补充）

手机看不了图，几乎都是同一个原因：**HTML 用相对路径引本地 png，单文件传出去就断图**。解法是把图**内嵌进 HTML**，做成「单文件自包含手账」。

| 项 | 要求 |
|---|---|
| 图片 | 全部转 `data:image/png;base64,...` 内嵌，**不留任何 `src="routes/..."`** |
| 体积 | 整份 HTML 目标 **≤ 8 MB**（7 张 1300×900 地图约 1.7 MB，base64 后约 2.4 MB，安全） |
| 远程依赖 | **零**：不引 CDN、不用远程字体、不 `fetch` 旁边的 JSON（`file://` 下同源策略会拦） |
| 校验 | 交付前跑：`grep -c 'src="data:image'`（应等于图数）、`grep -c 'src="http'`（应为 0）、`grep -c '<img'`（应为图数） |
| 保底格式 | 再出一份 **PDF**（Chromium 打印，`print_background=True`），微信里可直接预览，不依赖任何 App |

**PDF 兜底命令要点**（Playwright）：

```python
pg.evaluate("document.querySelectorAll('details').forEach(d=>d.open=true)")  # 展开全部折叠
pg.add_style_tag(content="""@media print{
  section,details{break-inside:auto!important}
  details .body{display:block!important}
  .scroll{overflow:visible!important}
  .rmap,.rmap-real{break-inside:avoid}}""")
pg.pdf(path=out, format='A4', print_background=True,
       margin={'top':'10mm','bottom':'10mm','left':'8mm','right':'8mm'})
```

**交付三件套**（同一份数据源渲染，改一处三处同步）：
1. `...-双方案.md` —— 可编辑正文
2. `...-双方案.html` —— **单文件、图已内嵌**，电脑双击即看、手机单文件也能看
3. `...-双方案.pdf` —— 手机预览 / 打印保底

**上云**：**优先飞书**（`lark-unified` 技能 / `lark-cli`，用法见 `references/online-doc-delivery.md`）；飞书不可用时改用腾讯文档。**连接器未启用（返回 `connector_disabled`）时不要卡住交付**——先交上面三件套，并提示用户在连接器面板启用后再上云。
